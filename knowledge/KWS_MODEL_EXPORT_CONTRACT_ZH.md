# KWS 模型导出契约（RTL8730E / Ameba River）

## 1. 目的

本文档用于约束唤醒词模型训练侧的导出类型，目标是同时满足以下要求：

- 适配 `RTL8730E` 上的 `TensorFlow Lite Micro`
- 尽量减小固件 `bin` 体积
- 避免项目侧为了兼容特定模型图而长期保留额外补丁代码
- 保持当前唤醒词链路可直接接入 `Ameba River`

当前项目已经验证：

- 现有 `bc_resnet_best.tflite` 可以运行
- 但该模型图中包含 `MEAN`
- 为兼容 `MEAN`，项目侧不得不额外加入 patched builtin `MEAN`
- 这会增加固件体积，也会增加后续维护成本

因此，后续推荐新增一个“嵌入式友好导出类型”，从训练/导出图层面直接规避该问题。

## 2. 适用范围

本契约适用于：

- 小欧管家唤醒词模型
- 面向 `Ameba River` 项目的 `int8 TFLite` 导出
- 运行环境为 `TensorFlow Lite Micro`
- 部署目标为 `RTL8730E`

本契约不要求替换训练框架，也不强制限定具体网络主干必须是 `BC-ResNet`。但导出结果必须满足本文约束。

## 3. 强制接口约束

### 3.1 输入约束

模型输入必须满足：

- 数据类型：`int8`
- 张量 rank：`4`
- 推荐 shape：`[1, 40, 98, 1]`
- 允许 shape：`[1, 98, 40, 1]`
- 输入含义：单通道 `log-mel` 频谱
- mel bin 数：`40`
- 时间帧数：`98`
- batch 固定为：`1`
- channel 固定为：`1`

补充说明：

- 当前固件优先支持 `40x98x1` 与 `98x40x1`
- 如果导出新类型，请优先统一到 `[1, 40, 98, 1]`
- 不要引入动态 shape
- 不要导出多输入模型

### 3.2 输出约束

模型输出必须满足：

- 数据类型：`int8`
- 总元素个数：`1`
- 推荐 shape：`[1, 1, 1, 1]`
- 可接受 shape：任意 rank，但总元素数必须严格等于 `1`
- 语义：单标量唤醒概率或唤醒分数

不允许：

- 多类别输出
- 多头输出
- 输出元素个数大于 `1`

### 3.3 量化约束

必须导出为原生全量化 `int8` 模型。

强制要求：

- 输入：`int8`
- 输出：`int8`
- 中间张量：`int8` 或符合 TFLM 常规要求的内部量化格式
- 不允许保留 `float32` 输入或 `float32` 输出
- 不允许依赖运行时 `Dequantize -> Float Head -> Requantize`

建议要求：

- 输入输出使用稳定的 affine quantization
- 导出报告中明确给出：
  - input scale
  - input zero_point
  - output scale
  - output zero_point

## 4. 算子契约

### 4.1 白名单算子

导出结果应尽量只包含以下算子：

- `PAD`
- `CONV_2D`
- `DEPTHWISE_CONV_2D`
- `ADD`
- `AVERAGE_POOL_2D`
- `LOGISTIC`

说明：

- `ADD` 用于残差分支
- `AVERAGE_POOL_2D` 用于全局平均池化或收缩头
- `LOGISTIC` 用于最终单标量概率输出

### 4.2 禁止算子

以下算子禁止出现在导出结果中：

- `MEAN`
- `FULLY_CONNECTED`
- `RESHAPE` 的复杂链式后处理版本
- `TRANSPOSE`
- `SOFTMAX`
- `DEQUANTIZE`
- `QUANTIZE` 作为图中补救性适配链路
- `CUSTOM`
- `SELECT_TF_OPS`
- `FLEX`

说明：

- `MEAN` 是当前项目侧补丁的根因，应从导出图层面去掉
- `FULLY_CONNECTED` 不是绝对不能支持，但当前目标是尽量缩减运行时和注册算子集合，因此本导出类型里建议直接禁止
- `TRANSPOSE` 和额外的 `RESHAPE` 链通常意味着训练侧没有按部署布局导出，会带来无效复杂度

## 5. 结构建议

推荐使用下面的输出头结构：

1. 主干网络输出特征图
2. 使用原生 `AVERAGE_POOL_2D` 实现全局平均池化
3. 使用 `1x1 CONV_2D` 作为分类头
4. 使用 `LOGISTIC` 输出单标量概率

允许：

- 主干仍然使用 `BC-ResNet`
- 主干有残差分支
- 主干中存在 `PAD + CONV_2D + DEPTHWISE_CONV_2D + ADD`

不建议：

- 导出后再离线改图把 `MEAN` 替换成别的算子
- 用脚本二次拼接分类头
- 依赖部署后修补张量布局

## 6. 导出实现要求

训练/导出侧需要新增一个明确的导出类型，建议命名参考：

- `tflite_int8_embedded_avgpool`
- `tflite_int8_rtl8730e`
- `tflite_int8_tflm_compact`

核心要求：

- 该导出类型必须在训练图或导出图阶段原生构造最终 head
- 不允许先导出旧图，再通过后处理脚本把 `MEAN` 替换成 `AVERAGE_POOL_2D`
- 导出逻辑必须稳定可重复，不依赖手工改图

## 7. 交付物要求

每次导出至少交付以下内容：

### 7.1 模型文件

- `.tflite`

### 7.2 导出报告

导出报告中必须明确包含：

- 模型文件名
- 模型文件大小（字节）
- 输入 shape
- 输出 shape
- 输入 dtype
- 输出 dtype
- 输入 scale / zero_point
- 输出 scale / zero_point
- 全部算子列表，按执行顺序列出

### 7.3 对比结果

必须提供与当前基线模型的对比：

- 验证集精度 / recall / FAR / FRR
- 关键词命中率
- 误唤醒表现

## 8. 验收标准

满足以下条件才可交付给嵌入式侧接入：

### 8.1 图结构验收

必须同时满足：

- 不包含 `MEAN`
- 不包含 `CUSTOM`
- 不包含 `SELECT_TF_OPS`
- 输出总元素数等于 `1`
- 输入布局符合本文要求

### 8.2 体积验收

建议目标：

- 模型大小尽量不高于当前 `~56KB`

可接受原则：

- 如果模型效果明显更好，可接受小幅增长
- 但必须解释增长是否值得

### 8.3 效果验收

必须满足：

- 相比当前 `bc_resnet_best.tflite`，验证集效果不能明显下降
- 若有下降，必须给出明确收益交换理由，例如：
  - 显著减少固件体积
  - 显著减少算子复杂度
  - 显著降低嵌入式侧兼容成本

## 9. 明确禁止事项

以下做法不接受：

- 先导出旧模型，再用脚本做图替换
- 交付包含 `MEAN` 的模型并要求嵌入式侧长期保留兼容补丁
- 交付输出元素数大于 `1` 的模型
- 交付 float 输入或 float 输出模型
- 交付依赖 `CUSTOM OP` 的模型

## 10. 训练侧建议回复格式

建议训练同事在交付时直接给出如下信息：

```text

模型文件:
模型大小:
输入 shape:
输出 shape:
输入 dtype:
输出 dtype:
输入 scale/zero_point:
输出 scale/zero_point:
ops 列表:
与 bc_resnet_best 基线对比:
是否包含 MEAN:
是否包含 CUSTOM/SELECT_TF_OPS:
```

## 11. 当前嵌入式侧结论

当前结论如下：

- 现有 `bc_resnet_best.tflite` 可以作为临时可运行方案
- 但它不是长期最优部署格式
- 从固件尺寸、兼容性、维护成本三个维度综合看，训练侧新增“无 `MEAN` 的嵌入式导出类型”更合适

如果训练侧能交付满足本文约束的新导出类型，嵌入式侧后续可以进一步尝试：

- 去掉项目侧 patched `MEAN`
- 收缩 KWS 运行时注册算子集合
- 进一步压缩固件体积
