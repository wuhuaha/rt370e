RTL8730E 4 寸板硬件固件说明书

基于 `doc/hard/`、`/root/ameba-rtos` SDK、当前项目绑定点和已记录的实板验证。边界停在 BSP/HAL/driver、pinmux、电源复位、下载和板级测量。

概览

A / 已闭合
PA2 / PA4
PDM_CLK 接 PA2，PDM_DAT1 接 PA4；DATA1 对应 DMIC3/DMIC4。
A / 已绑定
PB25
功放 AXS2033 的 SHUT/SD 控制网名 MUTE，项目覆盖为 `_PB_25`。
B / 待确认
DSI lane
原理图 D0/D1 两条 data lane，ST7102 init table 写 `SSD_LANE(1,0)`。
A / 下载边界
NAND
板上 GD5F1GM7UEYIGR SPI NAND，当前硬件使用 NAND profile。

音频输入

`CN7 -> PDM_CLK/PDM_DAT1 -> PA2/PA4 -> Audio HAL DATA1 -> DMIC3/DMIC4 -> AudioRecord`。已由实板记录证明能产生有效语音输入。

音频输出

`Audio HAL speaker -> APP_LINE_OUT -> LINEOUT_LN/LP -> AXS2033 -> CN2 speaker`。当前默认播放音量已调到满量程。

外设块说明

Power / Reset / Boot

固件可控制 LCD/Zigbee 子电源 enable，但不能假设 `CHIP_EN` reset 会清空所有外设电源状态。LCD/Zigbee 上电顺序要和 reset/boot strap 串行。

SPI NAND / Flashing

`U11 GD5F1GM7UEYIGR` 走 PC1-PC6 QSPI。当前硬件应使用项目 NAND profile，profile mismatch 先检查 wrapper 和下载模式。

PDM Microphone / Audio Capture

路径为 CN7 `PDM_CLK/PDM_DAT1` 到 RTL8730E `PA2/PA4`，再到 Audio HAL DATA1 `DMIC3/DMIC4`。问题定位先看 peak 和 PDM 波形。

Speaker / AXS2033 / Audio Output

`AMEBA_AUDIO_DEVICE_SPEAKER -> APP_LINE_OUT -> LINEOUT_LN/LP -> C76/C153 + R56/R57 -> AXS2033 -> CN2`。无声排查顺序：playback status、U7 VDD、U7 SD、LINEOUT、OUTP/OUTN、CN2。

LCD / Backlight / Touch

CN6 包含 DSI D0/D1/CLK、LCD power/reset/backlight、touch I2C/IRQ/reset。lane/timing 未闭合，touch `0x55` 只是候选。

BL702 Zigbee Subsystem

`Zigbee_PWR_ON -> VCC_3V3_Z -> BOOT_BL702 low -> release RST_BL702 -> UART1`。协议、波特率和升级流程仍需 owner 提供。

Wi-Fi / BT RF

RF matching 和天线选择属硬件/RF 边界。country、tx power 和 empty efuse fallback 涉及合规，变更前要硬件/RF review。

TH Sensor / IR / Debug

TH 只有 I2C FPC 线索；IR 需 PWM/载波和电流限制确认；CN1 暴露 USB/UART0，当前下载需要手动进入 download mode。

风险与来源

B

LCD lane/timing

可能导致白屏、花屏或误判背光。需要 panel timing sheet，并保持 lane config 可变。

B

AXS2033 SD

SD 电压未实测，功放可能处于错误模式。需要跨状态测 U7 pin1。

B

PDM L/R

槽位/顺序未由小板资料闭合。需要单麦近场测试，并将 mapping 保存在 board config。

A

BL702 protocol

UART 协议、波特率和升级流程缺失，Zigbee feature 不能安全集成。

Scope Audit

音频输出只描述 HAL-visible speaker route 到 LINEOUT、AXS2033 和 CN2；音频输入只描述 PDM pins 到 Audio HAL DMIC categories。显示/触摸通过 DSI/I2C/reset/backlight、init evidence 和 board validation 描述。避坑建议均绑定 schematic、datasheet、SDK、项目源码、runtime records 或明确假设。本文不把产品交互、应用会话行为、网络服务策略或 UI flow 作为硬件结论。
